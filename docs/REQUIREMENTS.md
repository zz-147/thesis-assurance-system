# 需求说明 v0.3：教师端 / 学生端（2026-10-25 更新）

> 本文是产品需求主文档；计划见 [PLAN.md](PLAN.md)，规则库见 [../rules/rules.json](../rules/rules.json)，规则集索引见 [../profiles/index.json](../profiles/index.json)，简历指标见 [METRICS.md](METRICS.md)。

## 1. 两个真实使用者（同一套规则引擎，两种输出）

### A. 教师 / 助教：规范文档 → 批量体检 + 真实性核验

```
上传规范文档（学院规范 / 课程模板，.docx / .txt / .md，PDF 后续接 docling）
  → 抽取文本 → LLM 抽取规则候选 → 教师确认 / 调整 → 保存为规则集 profile
  → 批量导入学生论文 / 文档
  → 逐份输出「合规报告」：格式问题清单 + 位置 + 实际值/期望值 + 修改建议
  → 真实性核验（新增）：文献是否真实存在、引用是否自洽、内容真实性线索
  → 班级汇总：共性问题 Top N、通过率、未核实文献清单
```

关键要求：
- 规范**不写死**：每门学科/课程可能不同 → 多 profile（多套规则 + 学科体系），换规范不改代码。
- 规则抽取结果**可人工审阅**：置信度 + 规范原文出处，教师勾选启用/改参数。
- 教师端只**诊断**，不自动改学生文件（避免"老师改了学生文档"的责任问题）。
- **先不做账号**：单机/校园内网运行；profile 先以 JSON 文件导出/分享，后续再加账号与多教师管理。

### B. 学生：上传文档 → 检查 + 一键修复

```
上传论文 / 文档（.docx）
  → 选择规范（老师分享的规则集 / 学院默认规范）
  → 输出问题清单 + 修改说明
  → 一键修复（仅安全项）→ 生成新 docx + diff 说明 + 修复后复检结果
```

关键要求：
- **只改格式，不改内容**：修复前后正文内容 hash 必须一致。
- **参考文献区域一律不动**：文献不让学生改，既不修复也不重排；只在检查报告提示。
- 修复输出新文件（`原名_fixed.docx`），原文件不覆盖；风险项（编号、题注、文献著录、字数）只给建议。
- 先本地/内网，不做登录。

## 2. 核心链路

```
规范文档 ──解析/LLM──> 规则候选 ──教师人审──> 规则集 profile（可导出分享）
                                                      │
学生文档 ──解析──> 角色识别 ──> 格式规则检查 ──> 问题清单 ──> 教师端：报告 + 汇总
                                    └──> 学生端：修复（safe 项）+ diff + 复检
教师端追加：文献解析 ──> Crossref/OpenAlex/arXiv 元数据核验 ──> 真实性报告（不改文档）
            引用一致性（文内 [n] vs 文献表、编号、上标、顺序）
```

- 检查与修复共用同一份规则集；教师端和学生端只是"渲染方式"不同。
- LLM 只负责：规范文本 → 结构化规则候选；不确定段落的角色判定；自然语言解释。**不直接改文档**。

## 3. 真实性核验（v0.3 新增，教师端）

### 3.1 文献真实性（可做，且必须"有证据、不武断"）

- 解析参考文献条目（GB/T 7714：期刊/图书/会议/学位论文/专利/标准/报纸/电子资源），抽取标题/作者/刊名/年份/DOI。
- 依次查询 **Crossref → OpenAlex → arXiv**（公开元数据 API），按标题相似度 + 年份/作者判断：
  - `verified`：高置信匹配（≥0.85），给出 DOI / 来源链接；
  - `likely`：部分匹配（0.60–0.85），需人工确认；
  - `not_found`：**仅表示"未在已查索引中找到"**，中文期刊可能未被收录 —— 不是"造假"；
  - `error`：网络/接口失败，重试或人工。
- 输出：逐条结论 + 匹配到的题名/年份/期刊/DOI/证据 URL；教师端汇总"未核实文献清单"。
- 隐私：只把**题名/作者**发给公开元数据 API，不上传论文全文；核验结果存本地。

### 3.2 引用一致性（可做，纯离线）

- 正文 `[n]` 引用编号是否都在文献表中 → 越界/缺失报错。
- 文献表中存在但正文未引用的条目 → 提示。
- 首次引用顺序是否递增（GB/T 7714 按引证先后编号）→ 报乱序。
- 正文引用是否上标（`w:vertAlign=superscript`）→ 报格式问题。
- 文献表编号是否连续、重复。

### 3.3 学生文档"内容真实性"（边界必须说清）

| 能做（本工具内） | 不能做 / 需外部服务 |
|---|---|
| 引用一致性、文献真实性（上两节） | **查重**（知网/维普/Turnitin/iThenticate）→ 需学校或第三方服务 |
| 图表/表/公式编号与正文引用的一致性（后续） | **AI 生成内容检测**（AIGC 检测）→ 无可靠本地方法，需第三方 |
| 数据与结论的明显矛盾线索（后续规则） | 学术不端定性 → 只能教师/学校人工认定 |

- 结论措辞红线：**不得输出"该文献是假的""该生抄袭/AI 生成"**；只能输出"未检索到 / 需人工核实 / 存在引用不一致"。
- 内容真实性如需进一步落地：预留"查重报告上传/接口"位置（教师把学校查重结果上传，系统与格式报告合并展示），不在本地做不可靠判断。

### 3.4 红线

1. 不自动修改参考文献；学生端修复白名单不包含任何文献/文字操作。
2. 不把真实学生文档/文献全文上传到第三方；文献核验只发题名/作者。
3. 不根据"未检索到"直接下结论；每条结论必须附证据与置信度。

## 5. 非功能需求

1. 确定性优先：同文档 + 同规则集 → 同报告；LLM 判定需缓存、可复现。
2. 可解释：每条问题给规则出处（`source`）+ 实际值/期望值；文献核验给证据 URL。
3. 可配置：规则参数不写死；多学科用 profile 切换。
4. 安全：修复白名单操作；文献区域只读；不改文字。
5. 性能：单份 10 页检查 < 10s；修复 < 30s；文献核验逐条 1–2s（限速）。
6. 可离线：格式检查/修复/引用一致性完全离线；文献核验联网可选（失败标 error，不阻塞其他报告）。

## 6. 验收标准

### 教师端
- [x] 上传一份新学科规范 → 生成 ≥ 20 条规则候选（带出处）→ 教师确认 → 新 profile 可用来检查。
- [x] 批量 ≥ 10 份学生文档：逐份报告 + 班级共性问题汇总 + 未核实文献清单。
- [x] 文献核验：真实文献给 DOI/链接；查不到的给"未索引，需人工核实"，绝不写"造假"。
- [x] 引用一致性：越界引用/未引用/乱序/未上标能检出；批量导出 xlsx/csv/html 可用。

### 学生端
- [x] 上传 → 报告 → 一键修复 → 下载新 docx，10 页文档全流程 < 1 分钟（Web 实测）。
- [x] 正文内容 hash 前后一致；参考文献区域逐字节/格式不变。
- [x] 修复后 P0 规则通过率 100%（合成评测）；每个修复项有说明；原文件不覆盖。

## 8. 待确认问题（不阻塞开发）

1. **LLM API**：已定 **DeepSeek**（`deepseek-chat`），key 通过环境变量 `TAS_LLM_API_KEY` 提供；**当前尚未生效**，设置命令：`setx TAS_LLM_API_KEY "sk-..."`。设置后即可跑 `tas spec parse` 实测。
2. **规范文档格式**：老师给的是 Word 还是 PDF？PDF 需要先转 docx 或接 docling。
3. **查重/AIGC**：学校是否有查重系统导出报告？如果有，教师端只需预留"上传查重报告"入口。
4. **评测数据**：哪些同学的文档可脱敏用于评测（决定简历数字可信度）。
5. **分享方式**：老师分享 profile 用"导出 JSON 文件 + 发链接"可以吗？（账号以后再做）

## 9. 明确不做（边界）

- 不代写、不润色、不改正文内容、不修改参考文献；不做查重；不做 PDF→Word。
- 不自动判定学术不端（抄袭/AI 生成/文献造假）——只给核验状态与证据，由教师/学校认定。
- 不把学校模板/学生文档/文献全文放进公开仓库或第三方服务。
